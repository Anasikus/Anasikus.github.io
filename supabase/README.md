# Отзывы: настройка Supabase

Раздел «Отзывы» и страница модерации `/admin` работают через
[Supabase](https://supabase.com) — бесплатную базу данных, к которой
сайт обращается напрямую из браузера. Пока переменные ниже не
прописаны, раздел и страница на сайте просто не показываются.

## 1. Создать проект

1. Зарегистрируйтесь на [supabase.com](https://supabase.com) (можно
   через GitHub).
2. New Project → любое имя, регион — ближайший (Frankfurt/EU
   подойдёт), пароль базы данных придумайте и сохраните куда-нибудь
   (для повседневной работы он не понадобится).
3. Подождите минуту, пока проект создаётся.

## 2. Создать таблицу отзывов

1. В проекте слева откройте **SQL Editor → New query**.
2. Скопируйте содержимое файла [`schema.sql`](./schema.sql) из этой
   папки, вставьте и нажмите **Run**.
3. Если ваш логин для входа в модерацию будет **не**
   `nastyadavydova20@gmail.com` — замените почту во всех четырёх
   местах файла на свою, до того как нажать Run.

## 3. Завести логин для модерации

1. Слева: **Authentication → Users → Add user**.
2. Впишите свою почту (ту же, что в `schema.sql`) и придумайте
   пароль. Галку «Auto Confirm User» включите — иначе Supabase
   попросит подтвердить почту письмом.
3. Этот логин и пароль — то, чем вы будете заходить на
   `ваш-сайт/admin`. Больше нигде вводить его не нужно.

## 4. Взять ключи для сайта

1. Слева: **Settings → API**.
2. Скопируйте **Project URL** и **anon public** ключ (не
   `service_role` — тот секретный и в сайт не идёт).
3. Локально: скопируйте `.env.example` в `.env` (если ещё не
   сделали для EmailJS) и впишите:
   ```
   VITE_SUPABASE_URL=...
   VITE_SUPABASE_ANON_KEY=...
   ```
4. Для опубликованного сайта: **Settings → Secrets and variables →
   Actions** в репозитории на GitHub → добавьте `VITE_SUPABASE_URL`
   и `VITE_SUPABASE_ANON_KEY` туда же, где уже лежат ключи EmailJS.
   Дальше сборка сама подхватит их (см.
   `.github/workflows/deploy.yml`).

## Как это защищено

`anon` ключ — публичный по замыслу Supabase, его можно смело
держать в коде сайта: он не даёт доступа сам по себе, доступ
регулируют правила (Row Level Security) из `schema.sql`:

- добавить отзыв может кто угодно, но статус ему всегда
  принудительно ставится «на проверке» — минуя код страницы это не
  обойти;
- читать может кто угодно, но только отзывы со статусом
  «одобрен»;
- видеть все отзывы, одобрять, отклонять и удалять может только
  тот, кто вошёл под почтой из шага 3, — то есть вы, на странице
  `/admin`.

Бесплатного тарифа Supabase (500 МБ базы, без карты) для отзывов
хватит с большим запасом.
